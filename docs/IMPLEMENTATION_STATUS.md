## 补充 — 扩充诊断题库（2026-11-09）

之前每项技能每级只有 2–3 道题，而且同样合适的题总是按固定顺序出，重新诊断时经常是同一份卷子。

### 已完成

- **题库从 70 题增加到 126 题**（`src/content/assessment/diagnostic-v1.json`，原创，待 owner 复核）：词汇、语法每级 5 道，阅读、听力每级 4 道，Pre-A1 到 C2 每一格都补齐。新题沿用原来的写法：词汇有认词（选意思）和回忆（写出单词或搭配），语法覆盖各级的典型结构（be 动词、复数、进行时、可数不可数、定语从句、虚拟、倒装等），阅读是告示、短信、短文和观点段落，听力是数字、时间、日常对话和带态度的说法。正确选项的位置按题目 id 分散。旧题一字未改，题库版本仍是 `diagnostic-v1`，旧诊断记录照常有效（D103）。
- **重新诊断会换题**：出题规则不变（答对升一级、答错降一级，最多 24 题，上次做过的题排在后面），同样合适的几道题之间按会话打乱顺序。同一次诊断里刷新页面不会换题；不同次诊断抽到的题不同。

### 测试结果

| 命令 | 结果 |
|---|---|
| `npm run lint` / `npm run typecheck` | ✅ |
| `npm run test` | ✅ 25 个文件，200 个测试（新增 2 个：每项技能每级题数达标、选项和题干不重复、填空答案不为空；同一会话顺序固定、不同会话抽到不同的题、上次做过的题仍然靠后） |

### 已知限制

- 新题的难度和区分度仍是人工估计，要等有了真实作答记录再校准。
- 每次诊断最多 24 题，估计结果的把握程度仍然最多到“中”；题库变大只是让重测不重复，不会让单次诊断更准。
- 全部答错的学习者会一直停在最低一两级，那两级每项技能只有 8–10 道题，连续重测仍可能碰到做过的题。

## 补充 — 流利度练习（2026-11-09）

四条主线里的“流利度”（规格 §2.2）之前一直是 0。这一步补上：用已经会的内容，把英语练得更快、更顺。

### 已完成

- **三种练法**（`/fluency`，练习菜单里的“流利度”；练习页是不带导航的专注页面）：
  - **快速阅读**：点“开始计时”后默读，读完点“读完了”；原文收起，回答这篇材料的理解题。结果显示每分钟词数、答对几题、正确答案；答对不到 70% 时保存但不计入速度（D101）。
  - **重复朗读**：同一篇大声读三遍，每遍计时，结果显示三遍的速度和第三遍比第一遍快了多少，和上次读这篇的最后一遍比较。
  - **限时复述（4/3/2）**：先读原文（不计时），然后不看原文、看着按原文顺序排的提示词讲三遍，时间一次比一次短（Pre-A1–A1 60/45/30 秒，A2–B1 90/60/45 秒，B2 以上 120/90/60 秒），时间到自动停；每遍讲完自评，两遍之间可以再看一眼原文。
  - 不录音、不需要麦克风、不用 AI，也不纠错。
- **材料**（D100）：只列出读完过的、或比你当前阅读 / 听力估计低一级以上的阅读和听力材料，没练过的排在前面；其他材料也能打开，会提示“这篇你还没读完过”。
- **记录**（`0013_fluency.sql` 的 `fluency_attempts`）：每次完成的练习一条（练法、材料、等级、词数、每一遍的用时和速度 / 限时 / 自评、理解题得分、学习时长），按请求 id 幂等，重试不会重复保存。速度在服务端按材料词数计算，不可能的速度、超时、轮数不对、没答完题都会被拒绝，并给出中文说明。
- **流利度页**：推荐现在练哪篇、用哪种练法；本周流利度分钟数和建议目标；阅读速度（最近 3 次平均，和再之前 3 次比较，最近记录表）；最近的练习。
- **计入学习时间**：流利度练习的时长（每次最多 20 分钟）进入每周学习时间的“流利度”一栏、长期趋势和“回来学习”的判断。今日页“流利度练习在后续阶段加入”的提示改成了去练习的链接。
- **今日计划**（D102）：本周流利度不足目标、今天还没练过时，在 25 分钟以上的计划里加一个 5 分钟的流利度任务（写明为什么选这篇、本周已练多少），做完自动打勾；不会把主线课程挤到 8 分钟以下，PTE 也不会占它的时间。

### 已知限制

- 只计时、不听：应用不知道你是不是真的大声读了、讲了多少内容，速度和自评都靠自觉。
- 规格里的“重复对话”没有单独做：可以在课程里重听、跟读对话，或在口语练习里重复同一个情景。
- 快速阅读用的是材料自带的理解题，读过的文章再练时可能记得答案；材料多了以后可以换成专门的速读题。
- 内置材料最长约 210 词，快速阅读一次只要一两分钟；更长的速读文本要等以后补充材料。

## 大步 3.3 — Speaking Lab 与实时语音（2026-11-08）

> 和 3.1、3.2 一样，这一步**只用本地模拟 AI 验证**。实时语音按 OpenAI Realtime 的 WebRTC 接口实现，但没有对真实接口跑过。

### 已完成

- **数据库**（`0009_speaking.sql`）：
  - `speaking_attempts`：任务、方式（实时 / 标准语音 / 文字）、服务商和模型、老师说话的等级、开始前的同意选择（保存转录 / 保存录音）、转录（同意时才有）、说话次数和词数、录音 id、反馈和置信度、时长、结束原因、实时连接次数和最近一次临时凭证的过期时间（不存凭证本身）；
  - `study_preferences` 新增 `save_speaking_audio`（默认关）和 `save_speaking_transcripts`（默认开），作为每次练习前的默认选择。
- **口语任务**（`src/content/speaking/tasks.json`，原创，待复核）：13 个任务覆盖七种题型——朗读、跟读复述、简单回答、引导对话、情景对话、故事复述（基于内置材料，可以收起原文）、观点表达，Pre-A1–A2。
- **三种练习方式**（规格 §5.10）：
  - **实时对话**（WebRTC）：浏览器把 SDP offer 发给本应用的服务端；服务端检查权限、限流，向服务商申请一个 **60 秒、只用这一次** 的临时凭证，用它完成 SDP 交换后丢弃，只把 answer 返回浏览器。之后语音直接在浏览器和服务商之间传输。状态有连接中 / 在听你说 / 正在想 / 老师在说话 / 已结束 / 连接中断；可以按按钮打断，也可以直接开口打断。连接超过 15 秒没成功、断线、麦克风被拒，都会说明原因，不会一直转圈，并释放麦克风；可以重连（每次练习最多 3 次连接）、改用标准语音模式，或者直接结束看反馈。时长上限默认 10 分钟（`AI_REALTIME_MAX_MINUTES`），到时自动结束。离开页面会断开并释放麦克风，回到页面时不会自己重连。
  - **标准语音模式**：录一句 → 转写 → 老师回复（文字先出来）→ 语音合成朗读。页面写明这不是实时对话。没有配置语音合成时用浏览器朗读，并标明。每个请求有超时，失败时说明原因；同一次练习里可以随时改用文字回答。
  - **文字回答**：没有麦克风时也能做对话类任务。
  - 浏览器不支持 WebRTC 时，页面说明并只提供标准语音模式；没有配置实时模型或转写模型时，对应的按钮不出现，服务端也会拒绝并说明原因。
- **朗读 / 跟读**：逐句录音、转写，按词对照原句，标出没被识别到的词（“可能是漏读，也可能是转写没听清，不是发音评分”）。跟读默认先听后看文字。
- **老师的说话方式**（规格 §10.2）：按学习者的听力 / 词汇 / 语法估计决定等级；初学者用短句和高频词，语速自然偏慢但不拖长；每次只问一个问题；卡住时给关键词或句型；先回应意思，再只纠正最重要的一处；可以用中文简短解释；发音只说具体的音、重音或口型，口音不算错误。
- **会后反馈**：任务完成、能不能听懂、流利度、语法（最多 3 条，必须引用学习者真正说过的话，否则丢掉）、词汇、自我纠正、做得好的地方、能力证据、最值得先练的一两点、下一步。**不评价发音**（反馈只根据转写文字，页面写明），置信度最高为“中”，说得少时为“低”，固定写明“不是 PTE 或任何官方考试的评分”。把握中等以上的语法问题进入错误本（来源“口语”）。反馈失败时练习照样结束，保存了转录就能重新生成。
- **隐私**（规格 §11.2、§14.2）：开始前说明声音会发给哪个第三方服务（模拟 AI 时说明不会发出），并让学习者选择是否保存转录、是否保存录音（只录自己的麦克风，默认不保存）。结果页可以重听录音、看逐轮转录、删除录音（文件和数据库记录一起删，转录和反馈保留）、删除整次练习。设置里可以改默认选择、查看保存了多少次练习和录音、一键全部删除。
- **成本控制**：实时连接、转写、语音合成都记入用量（费用记为“未知”，因为不按文本 token 计价），预算用完时不能开始；每人每 10 分钟最多 6 次实时连接；语音合成结果在进程内缓存，跟读句子反复听不重复付费。
- **其他**：口语入口标为“可以使用”；完成的口语练习计入每周学习时间（输出类）；设置里显示实时 / 转写 / 合成各自是否已配置；新增 `AI_VOICE`、`AI_REALTIME_MAX_MINUTES`（`.env.example` 和 docker-compose 已同步）。

## 大步 2.3 — 内容导入（2026-11-07）

### 已完成

- **数据库**（`0006_imports.sql`）：

- **解析器**（不用 AI，全部有测试）：
  - 文本 / Markdown：去掉 Markdown 标记（粘贴的内容像 Markdown 时也会自动处理），按段落和句子切分，Mr.、e.g.、a.m.、U.K. 这类缩写不会被切断；
  - SRT / WebVTT：只用真实时间戳，读不出的字幕跳过并提示，支持 VTT 的说话人标记；
  - CSV / TSV 词表：支持引号字段；有表头时按列名（word / meaning / example / ipa / pos，中英文列名都认）识别，没有表头时按“单词、释义、例句”读取；缺释义或文件内重复的行跳过并提示；
  - 限制：文本 2 万字符、400 句、500 个词、文件 2 MB、音频 50 MB。超出部分截断并提示，不会悄悄丢掉。
- **难度分析**：词数、句数、平均和最长句长、不同的词、长句数，以及“词汇库里已有的词”的占比。建议等级只按平均句长粗略估计，页面上写明了，可以改。AI 分析在 Phase 3。
- **导入流程**（“我的材料”`/library`，规格 §5.14）：选用途 → 粘贴或选文件（听力可以加音频）→ 必须选版权状态（我自己写的 / 合法获得、仅供个人学习 / 公有领域 / 有授权），可以写来源备注 → 解析成**草稿** → 预览页显示提示、难度数字、分句（字幕带时间）或词表（标出已有的词）→ 确认导入（可以改标题和等级）或放弃草稿。页面上写明只导入有权使用的材料、仅供个人学习、不支持绕过付费或 DRM。
- **导入后**：
  - 文本 → 阅读室（标“我的材料”）。没有生词表，查词会在课程词汇和你导入的词表里找。
  - 字幕 + 音频 → 听力工作室，用真实音频：按时间轴逐句播放、上一句 / 下一句、单句循环、A-B 循环、6 档语速（浏览器保持音调）、逐句听写也播放原音。没有时间轴的文本配音频时只能整段播放，并提示改用字幕；没有音频时用浏览器朗读。
  - 词表 → 自己的词条 + 复习卡（跳过词汇库里已有的词）。没有例句的词，复习卡不显示空的例句行。

  - `study_plans` / `study_plan_tasks`：每天一份计划，保存顺序、跳过状态和原因。
- **学习者档案与偏好**：第一次用到时自动按默认值创建。时区和新卡上限改为读取学习偏好，复习页、词汇页、今日页、进度页都使用学习者自己的时区。
- **引导**（`/onboarding`，规格 §4.1）：欢迎 → 讲解语言 → 学习目标（多选）→ 每周天数和每次时长 → 自评 → 诊断 → 第一周计划。
  - 每一步都保存，中途离开，下次从同一步继续；任何时候都能“跳过引导”。
  - 引导不会强制跳转；今日页顶部会提示“先花几分钟完成首次引导”。
  - 第一周计划写明节奏、每次学习由哪些部分组成、从哪节课开始以及原因。
- **基础诊断**（`/assessment`，规格 §4.2）：
  - 题库 `diagnostic-v1`：词汇、语法、阅读、听力四项，Pre-A1 到 B1 各级都有题，共 40 题。每题都标了 CEFR 等级、难度和区分度，状态是“待 owner 复核”。
  - 自适应：答对升一级、答错降一级；词汇、语法各最多 6 题，阅读、听力各最多 4 题，约 20 题。自评只决定从哪一级开始，不会直接当成水平。
  - 有“不会”按钮，不鼓励瞎猜；每题答完显示对错和简短解释；任何一部分都能跳过；可以暂停、下次继续。
  - 只在服务端判分，答案不会发到浏览器；只能回答当前这道题；重复提交返回已保存的结果。
  - 写作是选做：样本会保存下来方便以后对比，但不打分（自动写作评估在 Phase 3）。口语诊断明确说明会在 Phase 3 上线。
  - 结果页每项都写明“约 X 级”、把握程度和依据的题数；短诊断的置信度最多为“中等”；最难的题都答对时提示“实际水平可能更高”；明确说明不是官方 CEFR 认证。
- **今日计划**（`/today`，规格 §4.3、§4.4）：
  - 优先级：到期复习 → 当前课程（上次学到一半的课优先）→ 意义输入（重听学过课程里的对话）→ 输出（再做一次学过课程里的口语任务）。按所选时长分配分钟数，某一块没有内容时，时间顺延给课程。
  - 每个任务都写明推荐原因（例如“10 张卡片到期”“你上次学到一半”“根据诊断的初步估计从 A1 开始”）。
  - 可以切换 15 / 25 / 40 / 60 分钟、只复习；可以上移 / 下移；跳过时要选一个原因（时间不够、有点累、太难、太简单、不感兴趣、其他），可以恢复。重新生成计划时，跳过的任务仍保持跳过。
  - “已完成”不靠手动打勾，而是从真实记录推导：课程完成、到期复习做完、推荐之后在那节课里做了听力或口语练习。
  - 超过 2 天没学：计划降一档，标题显示 “Welcome back. Let's pick up where you left off.”。
  - 侧栏：到期复习数、当前课程、最近 7 天学习时间（按天、按四支柱）、最近加入的词、本周已学天数提示（不清零、不扣分，可以关闭）。
- **起点**：没开始任何课时，按诊断中词汇和语法较低的一项决定起点；如果课程内容还没到那个等级，就从现有内容的最高等级开始。前面的单元不锁定。
- **进度页**（`/progress`）：各技能估计（等级、把握程度、题数、来源和日期）、每个等级的课程完成度、词汇“看得懂 / 用得出”差距和状态分布、7 / 30 / 90 天保留率、最近 7 天四支柱学习时间。
- **学习时间统计**：来自课程每一步的用时和每次复习的用时，单条记录封顶（课程一步 5 分钟、复习一次 2 分钟），避免页面开着没学也算时间。课程步骤按技能和角色归入四支柱。
- **设置**：“学习者档案”（讲解语言、学习目标、时区、备注）和“学习计划”（时长、每周天数、每天新卡上限、每周天数提示）可以保存；可以重新走引导或重新诊断。

## 大步 1.2 — 词汇与 FSRS 复习（2026-11-07）

### 已完成

- **调度**：使用 `ts-fsrs` 6.0。
  - 配置：FSRS-7、目标保持率 90%、学习步骤 1 分钟 / 10 分钟、重学步骤 10 分钟、关闭随机抖动（fuzz）。
  - 算法本身没有自己重写。每张卡和每条复习记录都保存调度器版本号。
  - v6 的接口和旧版不同：异步创建调度器、卡片字段改为驼峰命名、恢复卡片时日期必须是 Date 对象。实现前做了实测验证。
- **数据库**（`0002_vocabulary.sql`）：
  - `vocabulary_entries`：词条，91 条，由 seed 从课程内容导入；
  - `user_vocabulary`：学习者的词汇状态与掌握度；
  - `review_cards`：完整的 FSRS 卡片状态，外加便于查询的冗余列；
  - `review_logs`：只追加、不覆盖，带幂等键，并保存复习前的卡片状态和调度结果。
- **卡片**：五种模板——英 → 义、听音识别（被动识别，自评）；义 → 英、听写拼写、语境填空（主动产出，需要打字）。
  - 加词时默认只生成“英 → 义”和“义 → 英”两张，其他类型在词条页按需添加。
  - 语境填空只在例句里确实包含这个词时才提供。
- **把作答转成评分**（服务端强制执行）：打字题答错一律记为“忘记了”；用了提示最多记为“很吃力”；可以手动标记“我的答案其实也对”（会记录在日志里）。
- **答错时的流程**（规格 §2.3）：先显示正确答案和例句，可以马上再写一次但不计入成绩，然后按“忘记了”记录，卡片会在本轮稍后再出现。
- **复习队列**：
  - 先复习到期卡片，再学新卡；每天最多 20 张新卡；
  - 同一个词一轮只出一张卡；同一个词的其他卡片在复习后 12 小时内不出现（兄弟卡间隔）；
  - 识别卡排在产出卡之前；
  - 处在短学习步骤里的卡片会在本轮内再次出现；
  - 连续遗忘 4 次的卡片标为困难项。
- **课程联动**：完成一节课后，课里的新词自动加入词汇库并生成复习卡，课程总结会显示“N 个新词已加入词汇库”。
- **复习工作台**（`/review`）：
  - 四档评分：忘记了 / 很吃力 / 记得 / 很轻松，并附通俗说明；
  - 支持快捷键（Enter、1–4）；
  - 听音和听写卡片自动朗读；
  - 有进度条和本轮总结；没有到期卡片时说明原因（例如今天的新卡额度已用完）。
- **词汇中心**（`/vocabulary`）：
  - 统计：总数、看得懂、会用了、到期 / 逾期、困难词；
  - 被动识别与主动回忆的稳定度对比；
  - 7 / 30 / 90 天保持率（不足 10 次复习时显示“数据不足”）；
  - 按状态筛选、搜索。
- **词条页**：每张卡片的状态、下次复习时间、复习和遗忘次数、暂停 / 恢复，按需添加卡片类型，复习记录，来源课程，以及困难词的处理建议。
- **导出**（规格 §5.4、§16.17）：词汇（含状态）和完整复习记录的 CSV。导出文件带 BOM，用 Excel 打开中文不乱码；以 = + - @ 开头的单元格会做处理，防止被当成公式执行。需要登录。
- **可复现**：从卡片创建时开始，按复习记录重放一遍，得到的状态和数据库里存的状态完全一致；修改调度器版本也不会破坏历史记录（有集成测试）。

## 大步 0.3 — 部署与验收（2026-11-07）

### 已完成

- **Docker 镜像**（`Dockerfile`）：
  - 多阶段构建：deps → builder → runner；基础镜像 `node:24-alpine`；Next.js `output: "standalone"`。
  - 运行镜像约 324 MB，以非 root 用户 `node`（uid 1000）运行。
  - 应用代码归 root 所有，只有 `.next` 和 `/app/data` 可写。
  - 构建时不需要任何密钥；镜像自带 `HEALTHCHECK`。
- **启动流程**（`docker/entrypoint.sh`）：先执行数据库迁移，再导入种子，都成功后才启动服务。迁移失败时应用不会启动，不会在迁移到一半的库上运行。
- **运维脚本打包**：迁移、种子和密码重设脚本用 esbuild 打成单文件（`dist/ops/*.mjs`），运行镜像里不需要 tsx 和开发依赖。
- **Compose**：
  - 新增 `app` 服务：等数据库健康后再启动；`init: true` 正确处理信号；用户文件放在命名卷 `appdata`（`/app/data`）。
  - 所有配置从 `.env` 显式传入，数据库连接串由 `POSTGRES_*` 拼出。
  - `APP_PORT` 可以自定义，也可以只绑定 `127.0.0.1`；数据库端口只绑定 `127.0.0.1`。
- **内容安全策略（CSP）**：采用 Next.js 官方“Without Nonces”方案。基于 nonce 的 CSP 会让所有页面变成动态渲染，和部分预渲染不兼容。
  - 允许内联脚本（Next.js 引导脚本和主题预加载脚本）。
  - 禁止外部脚本、插件（`object-src 'none'`）、被嵌入框架（`frame-ancestors 'none'`）、向外部提交表单和劫持 `<base>`。
  - 开发模式额外允许 `unsafe-eval` 和 WebSocket（热更新需要）。
  - 已确认开发和生产环境都没有 CSP 违规。
- **运维脚本**（bash，Linux / macOS / Git Bash 通用）：
  - `scripts/backup.sh`：数据库导出 + 用户文件归档 + 变量名清单（不含值）+ 带 SHA-256 的 manifest。
  - `scripts/restore.sh`：先校验再动数据；需要确认；替换数据库和文件；启动后等待健康检查。
  - `scripts/healthcheck.sh`：检查容器、健康接口、数据库、磁盘和 AI 配置，不打印密钥。
  - `scripts/update.sh`：拉取代码 → 备份 → 构建 → 重启（自动迁移）→ 健康检查；失败时打印回滚步骤。
  - 都支持用 `ENV_FILE` 和 `COMPOSE_PROJECT_NAME` 指定其他环境。
- **忘记密码**：`docker compose exec app node ops/reset-owner-password.mjs`（本地开发用 `npm run owner:reset-password`）。密码隐藏输入或从管道读入，不出现在命令参数里；重设后清除所有会话。
- **`npm start`** 改为和镜像相同的 standalone 方式运行（`scripts/start-standalone.mjs`，跨平台）；E2E 也用这种方式。
- **E2E**：新增 `E2E_BASE_URL` 模式，可以对已经部署的实例运行同一套测试。
- **截图**：`scripts/capture-screenshots.ts` 从真实部署截图，放在 `docs/screenshots/`。
- **文档**：README 按规格 §17 重写；新增 `docs/OPERATIONS.md`（部署、HTTPS / 反向代理、备份恢复、升级回滚、忘记密码、故障排查、数据与隐私）。
- **界面**：侧栏项目高度和分组间距收紧，1440×900 屏幕上导航不再需要滚动（加入账户区后 AI Tutor 和 Progress 被挤出了可视区域）。新增站点图标（`src/app/icon.svg`）。

### 过程中发现并修复

- **构建时调用了认证实例**：`getCurrentUser` 写成 `getAuth().api.getSession({ headers: await headers() })`，JavaScript 会先执行 `getAuth()` 再执行 `await`。在没有 `.env` 的 Docker 构建中，这会在预渲染阶段报环境变量缺失。改为先读取请求头。本地因为有 `.env` 掩盖了这个问题，干净的 Docker 构建发现了它。
- **Git Bash 路径转换**：Git Bash 会把传给 docker 的 `/app/data` 改写成 Windows 路径，已在脚本中关闭（`MSYS_NO_PATHCONV=1`）。
- **ESLint 检查了生成文件**：`dist/` 已加入忽略列表。

## 大步 0.2 — 数据与登录（2026-11-07）

### 已完成

- **数据库**：`docker-compose.yml` 中的 PostgreSQL 18（`postgres:18-alpine`），带健康检查和命名卷 `pgdata`，端口只绑定 `127.0.0.1`；时区 UTC。
- **Drizzle**：schema（`src/db/schema`）→ `npm run db:generate` 生成 SQL migration（`src/db/migrations/0000_init.sql`）→ `npm run db:migrate` 执行。没有使用 `drizzle-kit push`。
- **表**：`users`、`sessions`、`accounts`、`verifications`（Better Auth 核心表，UUID 主键、snake_case 列）、`app_instance`（单行表，保证只有一个 owner）、`cefr_levels`。
- **Seed 机制**：`src/db/seed/` 下的版本化 JSON + Zod 校验 + 幂等 upsert，`npm run db:seed`。首个 seed 为 7 个 CEFR 等级（规格 §3.1）。
- **环境变量**：`src/lib/config/env.ts` 用 Zod 校验，首次使用时才解析，构建时不需要密钥；`.env.example` 列出全部变量并注明必填 / 可选。

  - 邮箱 + 密码，**公开注册关闭**；owner 只能通过 `/setup` 创建。
  - 密码使用 **Argon2id**（`@node-rs/argon2`，OWASP 基线参数：19 MiB、2 次迭代、并行度 1），至少 10 个字符。
  - 会话存数据库，cookie 为 HttpOnly + SameSite=Lax，HTTPS 部署时自动加 Secure；关闭 Better Auth 遥测。
  - 首次初始化先原子“占用” `app_instance`，并发请求只有一个能成功；中途失败会释放占用，中断超过 5 分钟的初始化可以重来。

- **页面与流程**：
  - `/` 根据状态跳转到 `/setup`、`/login` 或 `/today`。
  - `/setup` 创建账户后直接登录；`/login` 对未知邮箱和错误密码显示同一条提示，不泄露账号是否存在。
  - 失败次数限制：同一邮箱 15 分钟 8 次、同一 IP 15 分钟 20 次、修改密码 15 分钟 5 次。
  - 侧栏底部显示当前用户和退出按钮。

- **访问控制**：
  - Proxy 把没有会话 cookie 的请求重定向到 `/login`（只是乐观检查）。
  - 真正的检查在服务端：页面内容在 `<Suspense>` 里经过 `requireOwner()`，每个 Server Action 自己重新验证会话。
- **`/api/health`**：返回应用版本和数据库状态（200 / 503），不暴露主机名、错误详情或配置。
- **安全响应头**：`X-Content-Type-Options`、`X-Frame-Options: DENY`、`Referrer-Policy`、`Permissions-Policy`；去掉 `X-Powered-By`。
- **新组件**：Input、TextField（label / 提示 / 错误与无障碍属性关联）、FormMessage、SubmitButton（提交中状态）、ConfirmDialog（Radix AlertDialog）。
