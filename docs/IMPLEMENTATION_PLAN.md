# LinguaBloom 实施计划与技术决策

> 依据：`LinguaBloom_Claude_开发规格.md` v1.0（规格基准日期 2026-11-07）
> 本文件随实施推进更新；每个阶段的真实完成情况见 `docs/IMPLEMENTATION_STATUS.md`。

## 1. 推进方式

- 每个 Phase 拆成 2–3 个**大步**，每个大步结束都必须可运行、可验证（lint / typecheck / test / build + 浏览器检查），再进入下一步。
- **界面优先**：先建设计系统和页面骨架，再接数据库与登录。页面骨架必须“诚实”：未实现的功能显示明确的空状态与所属阶段，不放假数据、不放点了没反应的控件。
- 只把真实可学习的内容标为 `published`；A2–C2 首版只做蓝图（`planned` / `draft`）。

### Phase 3 — AI Tutor 与语音

| 大步 | 内容 | 验收 |
|---|---|---|
| 3.1 AI 基础与 AI Tutor | Provider Adapter（统一接口，首个 OpenAI，返回结果一律经 Zod 校验，不把原始响应漏到业务层）；配置项补齐 `AI_TIMEOUT_MS` / `AI_MAX_OUTPUT_TOKENS` / `AI_MONTHLY_BUDGET`；用量记录（provider、模型、任务类别、耗时、token 与费用估算，不记密钥）和软预算（接近时提醒，超出后高成本功能暂停，可在设置里看到）；`ai_sessions` / `ai_messages`；AI Tutor 九种模式（讲解、练习、自由对话、情景角色扮演、纠错、AI 提问、陪你复习、阅读教练、听力教练），按各技能估计调整语言难度，只传必要的学习上下文，结构化回复（纠错、新词可一键加入词汇库、追问）、流式输出；阅读 / 听力页可以“问 AI”；会话按设置保存、可单条删除；设置页的 AI 状态与用量；未配置 AI 时其他功能照常可用 | 前端拿不到长期密钥；AI 难度随等级变化；Provider 出错时显示能看懂的原因；超预算策略生效（✅ 2026-11-07，模拟 AI） |
| 3.2 写作工作室与 AI 内容生成 | 写作任务（句子改写、日记、邮件、观点、摘要等）；分层反馈（任务完成度 → 内容 → 语法 → 词汇搭配 → 组织衔接 → 自然表达），带置信度、依据和限制说明，先改最重要的问题、示范可选，学习者写第二版并对比；语法类问题进入错误本（低置信度不进入）；生成内容一律先成草稿、校验、预览后才发布：AI 释义（补足生词表外的查词，结果缓存）、为导入材料生成生词表和理解题、按学习者水平生成分级阅读、根据错题生成专项微课 | 写作反馈结构经过校验并标明置信度；生成内容都要预览确认（✅ 2026-11-07，模拟 AI） |
| 3.3 Speaking Lab、实时语音与 Phase 3 验收 | 服务端签发短时效、单用途凭证，浏览器用 WebRTC 连接实时语音模型；连接 / 聆听 / 思考 / 说话 / 结束状态，可打断，断线不会无限加载，结束时释放麦克风；不支持 WebRTC 或连接失败时切到“标准语音模式”（录音 → 转写 → 文本模型 → 语音合成），页面写明；口语任务（朗读、复述句子、简短回答、引导对话、情景对话、故事复述、观点表达）；会后反馈（任务完成、可理解度、流利度、语法、词汇，发音只在模型可靠时给出，不因口音扣分，不冒充 PTE 官方评分）；录音前说明是否保存录音 / 转录、是否发给第三方，默认不存录音，可删除单次会话和录音；可选：用 TTS 为内置听力材料生成并缓存音频 | Phase 3 整体验收：前端无法获取长期密钥；可创建并结束语音会话；AI 难度按等级调整；失败时显示原因并降级；会话记录按设置保存 / 删除（✅ 2026-11-08，模拟 AI；可选的内置材料 TTS 音频未做） |

原始范围：Provider Adapter（首个 OpenAI）、Tutor 文本模式、结构化内容生成、写作反馈、WebRTC 语音会话、STT → LLM → TTS 降级、Speaking Lab、AI 成本与用量记录。

测试策略：自动化测试（单元、集成、E2E）都用一个**模拟 Provider**，不需要真实密钥，也不产生费用；真实 Provider 的连通性在有密钥时单独验证并记录。模型名称不写死，全部从环境变量读取，实现时按 Provider 的最新文档确定推荐值。

### Phase 4 — 评估与 PTE 专区

| 大步 | 内容 | 验收 |
|---|---|---|
| 4.1 能力评估与 can-do 证据 | `can_do_statements`（从课程单元内容导入：编号、等级、规格 §2.1 的十个技能维度、中英文描述、前置能力、证据类型、通过标准）和 append-only 的 `can_do_evidence`（来源：课程步骤、语法 / 阅读 / 听力练习、口语任务、写作；结果、置信度、时间）；每条 can-do 的状态（未开始 / 有证据 / 已展示）按通过标准计算，显示最近一次验证时间和证据链接；能力地图页（按等级和技能维度浏览）；**评估历史**：可以定期重新诊断，每项技能的估计时间线（来源、置信度、证据数），两次诊断对比；进度页补齐规格 §5.15 的图表（技能趋势、词汇被动 / 主动差距、保留率、阅读理解率、听力重放与理解率、语法薄弱点、口语任务完成、写作错误类别变化、四条主线时间分布），并注明“学习记录，不是官方 CEFR 认证” | 能力证据可以追溯到真实练习记录；评估历史保留每一次结果；单次练习不会直接改变 CEFR 等级（✅ 2026-11-08） |
| 4.2 PTE 专区：版本化数据、阅读与听力题型 | 实现前重新核对 Pearson 官方题型页（规格 §18.4），把来源 URL、复核日期写进 `exam_versions`；`pte_task_types`（22 类全部建档：所属部分、影响的技能、时间、评分方式说明，按版本保存）、`pte_rubrics`、`pte_prompts`（原创题目，带难度和版本）、`pte_attempts`（回答、客观评分、反馈、用时，绑定考试版本和题目版本）；每个题型的介绍页（官方说明和 AI 反馈分开展示）；**阅读 5 类、听力 8 类全部可练**，每类先放 3–5 道原创题：客观题按官方规则精确判分（含部分得分和扣分规则），听力里需要写的题（口头总结、听写）客观部分精确判分、其余给 AI 辅助反馈；计时模式；答错进入错误本；**音频**：配置了语音合成模型时一次性生成音频文件并缓存（进入备份），没配置时用浏览器朗读并标明——同一套机制也为内置听力材料生成音频（3.3 的可选项） | 至少一个代表性题型能完整练习并看到反馈；每次作答都绑定当前考试版本 |
| 4.3 PTE 口语写作题型、模拟练习、报告与 Phase 4 验收 | **口语与写作 9 类全部可练**（朗读、复述句子、看图描述（原创生成的图表）、复述讲座、简短回答、小组讨论总结、情景回应、写作摘要、作文），复用 Speaking Lab 的录音 / 转写和写作反馈，标明“AI 辅助反馈，不是 Pearson 成绩”；按部分组卷的计时模拟练习（可中途保存）；练习报告：按题型和技能的正确率 / 趋势、用时、常见错误、技能交叉影响说明；学习者把 PTE 设为目标时，今日计划加入 PTE 练习；新增考试版本时旧记录照常显示（版本切换测试）；全新 Docker 环境验收 | Phase 4 整体验收：用户可完成至少一个代表性任务类型的练习并看到反馈；数据能绑定当前考试版本；修改考试版本不会破坏旧记录 |

原始范围：技能评估历史、can-do 证据、PTE 数据模型（按 `exam_version` 版本化）、原创练习、计时模式、练习报告、官方题型来源和版本日期。

owner 的选择（2026-11-08）：22 类题型全部可练；听力音频在配置语音合成后由 AI 生成并缓存，否则用浏览器朗读。

PTE 的边界（规格 §5.13）：客观题可以精确判分；自由口语 / 写作只给 AI 辅助反馈和估计，不声称等同 Pearson 正式成绩，不做“AI 预测 79 分”这类不透明的总分；题目素材全部原创。

## 3. 技术决策记录

版本均于 2026-11-07 通过 npm registry 与随包官方文档（`node_modules/next/dist/docs/`）核对。

| # | 决策 | 理由 |
|---|---|---|
| D1 | **Next.js 16.4（App Router）+ React 19.3 + TypeScript 5** | 规格定案。TypeScript 7 已发布，但 Next 工具链默认配套 5.x，暂不升级。 |
| D2 | **启用 Cache Components + Partial Prefetching**（create-next-app 默认） | Next 16 推荐模型。约束：读取 cookies / headers / 数据库的组件必须放在 `<Suspense>` 内或使用 `use cache`；不能在根布局直接读 cookies。 |
| D3 | **Tailwind CSS 4**，通过 `@tailwindcss/turbopack` loader 接入 | 脚手架默认方式。设计令牌写成 CSS 变量，并在 `@theme inline` 中映射为 Tailwind 工具类。 |
| D4 | **UI 原语自建（shadcn 风格）+ `radix-ui` 按需使用** | 规格要求 shadcn/ui + Radix 按需取用并统一主题。先手写少量原语（Button、Card、Badge 等，使用 cva），变量命名兼容 shadcn（`--background`、`--primary` 等），以后可直接用 shadcn CLI 添加组件。 |
| D5 | **字体：`geist` npm 包（本地字体文件）+ 中文系统字体栈** | 不在构建时请求 Google Fonts，在受限网络环境下也能构建。阅读模式使用 Georgia 衬线栈。 |
| D6 | **主题：`data-theme` + `<head>` 内联脚本 + localStorage** | 按 Next 官方“preventing flash before hydration”指南，避免首屏闪烁且不破坏静态外壳。主题属于非敏感 UI 偏好，规格允许存 localStorage；登录后再同步到 `study_preferences.dark_mode`。支持 light / dark / system。 |
| D7 | **认证：Better Auth（邮箱 + 密码，数据库会话）** | 规格优先 Auth.js Credentials 或“同等成熟方案”。Auth.js 的 Credentials 模式只支持 JWT 会话，难以实现“注销全部会话”；Better Auth 原生支持数据库会话与会话撤销，并有 Drizzle 适配器。实施 0.2 前再次核对其官方文档。 |
| D8 | **PostgreSQL + Drizzle ORM / drizzle-kit migrations** | 规格定案。生产环境只运行 migrations，禁止 `drizzle-kit push`。 |
| D9 | **测试：Vitest 5 + Testing Library（单元/组件），Playwright（E2E，0.2 起引入）** | Vitest 不支持 async Server Component，此类组件用 E2E 覆盖（Next 官方说明）。 |
| D10 | **Node.js：`engines >= 24`；Docker 镜像用 `node:24-alpine`**；本机开发为 Node 26 | 规格指定 Node 24 LTS（维护期到 2028-04），镜像遵循规格；Node 26 已于 2026-10 进入 LTS，本机开发用它同样兼容。 |
| D11 | **包管理器：npm** | 规格中的命令均为 `npm run …`。 |
| D12 | **ESLint 9（脚手架锁定）** | `eslint-config-next` 16.4 使用 ESLint 9；ESLint 10 已发布，待 Next 配套插件跟进后再升级。 |
| D13 | **配色按 WCAG AA 微调**：`--muted` 用 `#676C80`；强调色增加 `*-soft` / `*-ink`；深色主按钮用深色文字 | 规格色值是“建议初始值”，原 `--muted` 在白底上约 4.4:1，不足 AA；强调色作为文字时对比度不足。 |
| D14 | **导航与功能注册表集中在 `src/lib/config/navigation.ts`** | 侧栏、底部导航、入口页和占位页共用一份数据；测试保证每个导航链接都有真实页面。这里只放应用结构，不放课程内容。 |
| D15 | **读取 URL 的导航组件放在 `<Suspense>` 中** | Cache Components 下，`usePathname` 在未预生成参数的动态路由（如 `/lesson/[lessonId]`）中会挂起；fallback 渲染无高亮的同一组链接。 |
| D16 | **只在浏览器存在的偏好，服务端渲染“未选中”而不是猜默认值** | 避免水合前短暂显示错误的选择（例如主题选择器）。 |
| D17 | **PostgreSQL 18**（`postgres:18-alpine`），驱动 **postgres.js** | 2026-11 时最新的官方镜像主版本；postgres.js 纯 JS、无原生依赖，Drizzle 原生支持。 |
| D18 | **Better Auth 定稿**：数据库会话、UUID 主键、snake_case 表；用自定义 hash 接入 Argon2id；关闭遥测 | 已核对 1.7.18 的源码与类型定义（D7 的落实）。`disableSignUp` 也会拦截服务端注册调用，所以 owner 通过内部 adapter 创建。 |
| D19 | **owner 唯一性用数据库保证**：`app_instance` 单行表 + `INSERT … ON CONFLICT … WHERE` 原子占用 | 不依赖“先查有没有用户”这种有竞态的判断；集成测试覆盖了 5 个并发请求的情况。 |
| D20 | **环境变量、数据库、认证实例都在首次使用时才创建**；只在请求时读数据库的组件先 `await connection()` | 让 `next build` 和 Docker 构建不需要运行时密钥，也不会在构建时连数据库。 |
| D21 | **认证类表单用 Server Action + `useActionState` + 共享 Zod schema** | 不依赖客户端 JS 也能提交，服务端校验是唯一可信来源。React Hook Form 留给 Phase 1 起更复杂的客户端表单（如 onboarding）。 |
| D22 | **项目改为 ESM**（`"type": "module"`）；`NODE_ENV` 不写进 `.env` | 脚本需要顶层 await 和 `import.meta`；`NODE_ENV` 由 Next / Docker 管理，写进 `.env` 会让测试进程把 development 传给 `next build` 导致构建失败。 |
| D23 | **测试分三层**：`test`（单元，无需数据库）、`test:integration`（测试库 `<库名>_test`）、`test:e2e`（Playwright，生产构建，端口 3200；Next 16 的 dev 输出在 `.next/dev`，与构建互不影响） | 测试库每次运行都会清空；名字不以 `_test` 结尾的库一律拒绝清空，防止误删开发数据。 |
| D24 | **修改密码成功后跳转到 `/settings?passwordChanged=1`**，而不是在原请求里返回成功 | Better Auth 会替换当前设备的会话 cookie；同一个请求里重新渲染仍会带着旧 cookie，被判定为未登录。 |
| D25 | **`output: "standalone"`**，镜像只包含追踪到的依赖；`npm start` 用同样方式运行（`scripts/start-standalone.mjs`） | Next 官方自托管方案；`next start` 不支持 standalone，本地和镜像保持一致。 |
| D26 | **CSP 不用 nonce**（允许内联脚本，严格限制其他来源） | Next 文档说明：基于 nonce 的 CSP 要求所有页面动态渲染，与部分预渲染不兼容。HSTS 和 `upgrade-insecure-requests` 交给 HTTPS 反向代理，以免纯 HTTP 的局域网部署失效。 |
| D27 | **迁移、种子、密码重设脚本用 esbuild 打成单文件放进镜像**；容器启动时先迁移、再导入种子，成功后才启动服务 | 运行镜像不需要 tsx 和开发依赖；迁移失败时应用不会在不完整的库上运行。`@node-rs/argon2` 是原生模块，不打包，运行时从 standalone 的 node_modules 加载。 |
| D28 | **Compose 里显式列出应用的每个环境变量**（不用 `env_file`），`DATABASE_URL` 由 `POSTGRES_*` 拼出 | 应用拿到哪些配置一目了然；同一个 `.env` 既能用于 `npm run dev`（连 localhost），也能用于 Docker（连 `db`）。 |
| D29 | **备份格式 v1**：`database.dump`（pg_dump 自定义格式）+ `appdata.tar.gz` + `env.template`（只有变量名）+ 带 SHA-256 的 `manifest.txt`；恢复前先校验 | 规格 §11.3。数据库和文件必须一起备份、一起恢复；校验失败时不动现有数据。 |
| D30 | **忘记密码用服务器端命令重设**（`ops/reset-owner-password.mjs`），不做邮件找回 | 单用户私有部署没有邮件服务；能在服务器上执行命令就等于拥有这台机器。重设后清除所有会话。 |
| D32 | **课程内容写成 `src/content/` 下的 JSON 文件**，用 Zod 校验，静态 import 后由 seed 导入数据库 | 内容可以审阅、可以版本化，也能打包进 Docker 镜像。测试会校验每个文件，内容出错时 CI 直接失败。 |
| D33 | **答案只在服务端判分**；发给浏览器的步骤去掉答案和解析，选项和词块用固定种子打乱 | 学习数据可信，前端拿不到答案。固定种子保证服务端渲染和浏览器渲染的顺序一致。 |
| D34 | **课程进度 = 只追加的作答记录 + 续学指针**；首次成绩只看每步第一次作答 | 符合规格 §2.3 和 §5.3：答错可以立即重试，但重试不算记住；历史记录不会被覆盖。 |
| D35 | **Phase 1 朗读用浏览器 Web Speech API**，速度偏好存在浏览器本地 | 不需要 AI 和费用，离线也能用；界面如实标明“浏览器朗读”。Phase 3 换成生成的音频。 |
| D36 | **口语录音只留在页面内**（blob URL），不上传；开放任务采用“先做、再看示范、再自评” | 隐私优先（规格 §7.7、§11.2）；没有 AI 时不伪造评分。 |
| D37 | **课程学习器放在单独的 `(focus)` 路由组**，没有侧栏和底部导航 | 规格 §2.7：一个页面只有一个主要任务，减少干扰。 |
| D38 | **FSRS 用 ts-fsrs 6 的 `DefaultScheduler`（FSRS-7），关闭 fuzz** | 不自行复制算法（规格 §2.3）。关闭 fuzz 后，按复习记录重放能得到完全相同的状态，可以被测试证明。代价是同一天加入的卡片到期时间更集中。 |
| D39 | **卡片状态存完整 JSON，另存查询用的冗余列**（`due_at`、`state`、`stability` 等）；复习记录保存复习前状态和调度结果 | 当前状态可以随时由记录重建；查询队列不用解析 JSON。 |
| D40 | **默认两张卡（识别 + 产出），其余按需添加** | 规格要求按需生成，避免一个词自动生成十几张卡；同时保证有“看得懂”和“用得出”两方面的证据。 |
| D41 | **评分规则在服务端强制执行**：打字题答错记为“忘记了”，用了提示最多记为“很吃力”，允许手动标记答对并记入日志 | 规格 §2.3：由应用把作答转成可靠评分，再交给 FSRS 调度。 |
| D42 | **兄弟卡间隔 12 小时，一轮一个词只出一张卡；每天新卡默认 20 张** | 避免同一个词的几张卡集中出现；1.3 起新卡上限读取学习偏好（0–100）。 |
| D43 | **导出 CSV 时加 BOM，并对可能被当成公式的单元格做处理** | Excel 打开中文不乱码，同时防止 CSV 公式注入。 |
| D44 | **诊断用阶梯式自适应**：答对升一级、答错降一级；每项最多 6 / 6 / 4 / 4 题；估计取“至少一题答对且正确率 ≥ 50%”的最高等级；短诊断置信度最多“中等”；自评只决定起始等级 | 规格 §4.2：分层、能跳过、不让初学者连续面对难题，并诚实说明不确定性。阶梯法简单、可解释、可测试；题量积累后再换 IRT。 |
| D45 | **起点取词汇和语法估计中较低的一项**，不锁定前面的单元；课程内容还没到该等级时，从现有最高等级开始 | 课程先打基础；规格 §3.1 要求有前置提示但不强制锁课。 |
| D46 | **今日计划按学习者本地日期保存**；“已完成”从真实记录推导，只算任务推荐之后的练习；重新生成时保留跳过和原因 | 规格 §4.3、§4.4：计划要稳定、可调整、可解释，不能靠手动打勾“作假”。 |
| D47 | **超过 2 天没学就算回归**：当天计划降一档，并显示欢迎回来 | 规格 §4.4：久未学习后先减负、先复习，不让人一回来就被大量任务压垮。 |
| D48 | **学习时间来自作答和复习的用时，单条封顶**（课程一步 5 分钟、复习一次 2 分钟），按步骤的技能和角色归入四支柱 | 规格 §2.2、§5.1：统计要来自真实记录；封顶可以避免页面开着没学也算时间。 |
| D50 | **查词用每篇文章自带的生词表 + 课程词汇，不内置大词典** | 体量小、释义质量可控，并且和文章语境一致；生词表外的词如实显示“暂无释义”，AI 释义在 Phase 3。曾考虑导入开源词典 ECDICT（MIT），因数据量大、释义质量参差不齐而暂不采用（owner 选择）。 |
| D51 | **听力材料没有录音时用浏览器朗读，不伪造时间戳** | 规格 §5.7：没有时间戳就不假装能逐词高亮；逐句播放、循环、变速用朗读实现，A-B 循环等导入真实音频后再提供。 |
| D52 | **学习时长只在页面可见并且最近有操作时计算**，每段最多 60 秒 | 让“意义输入”时间来自真实阅读和听力，而不是页面开着没人看。 |
| D53 | **错误本以“错误类别 + 知识点”为一条**，每次出错另存一条只追加的记录 | 规格 §5.12：要能看出“同一个错误”反复出现，又保留每次的原始内容。 |
| D54 | **出现 2 次触发补救（3 题对 2 题），隔一个本地日再测（2 道新题、尽量换题型、全对）才算解决**；复发自动重开 | 规格 §2.8：补救后换语境再测，检验迁移；隔天再测避免只测到短时记忆。 |
| D55 | **练习驱动的技能估计**：最近 40 次，至少 4 题且正确率 70% 以上的最高等级；少于 8 次不写，有变化才写 | 让估计随真实练习更新，同时不让历史记录被小波动刷屏；把握程度按证据量诚实标注。 |
| D56 | **造句题先自评**：写句子 → 对照检查清单 → 看示范；不自动判对错，也不记入错误本 | 没有 AI 时无法可靠判断开放句子，宁可让学习者自评，也不假装能自动批改。 |
| D57 | **导入先存草稿，确认后才进入学习库**；必须选版权状态，导入内容只属于本人 | 规格 §5.14、§9.5、§12：防止误导入，也明确只供个人学习。 |
| D58 | **上传走路由处理器（multipart），不用 Server Action**；音频要同时通过类型白名单和文件头检查 | 音频可能有几十 MB，超过 Server Action 的请求体限制；文件头检查能挡住伪装成音频的文件。 |
| D59 | **音频由登录后的 `/api/media/[id]` 提供，支持 Range**，文件放在 `STORAGE_ROOT/media/<用户>/`，数据库只存相对路径 | 只有本人能取；Range 让播放器能跳转（逐句、A-B 循环）；相对路径方便搬迁，文件随 `appdata` 卷一起备份。 |
| D60 | **难度分析不用 AI**：只给能解释的数字（句长、词数、词汇库覆盖率），建议等级按句长粗估、可改 | 没有 AI 时不假装能判断 CEFR 等级，AI 分析在 Phase 3 加入。 |
| D61 | **自动化测试一律用模拟 Provider**（`AI_PROVIDER=mock`），真实服务在有密钥时单独验证 | 测试不依赖网络和费用，结果确定；owner 选择暂不提供密钥。模拟回复标明“模拟”，不会被误认为真实 AI。 |
| D62 | **OpenAI 用 Chat Completions + JSON 模式**，结构用 Zod 校验，不依赖服务商的 JSON Schema 功能 | 兼容更多 OpenAI 兼容服务（`AI_BASE_URL`）；不管服务商返回什么，都由我们自己校验，确保格式正确。 |
| D63 | **教学模式返回结构化回复，自由对话和角色扮演流式返回自然文本**，需要时单独“检查这句” | 规格 §5.9；对话时不打断每个小错误，纠错由学习者自己决定。 |
| D64 | **Tutor 的语言难度取阅读、词汇、语法估计中最低的一项** | 规格 §10.1：“不因某项能力强就假设其他能力也强”。 |
| D65 | **软预算按学习者本地月份计算，80% 提醒、100% 暂停（不调用服务商）**；没有价格时只按已知部分计算并明确提示；每人每分钟 20 次 | 规格 §7.6 成本控制；费用估算不准确时不装作准确。 |
| D66 | **写作先保存再请求反馈**，AI 失败不丢稿、可重试 | 学习者写的东西是最重要的数据，不能因为外部服务失败而丢失。 |
| D67 | **AI 指出的问题必须引用学习者原文，否则丢弃**；语法点只能从现有列表里选 | 防止模型编造错误；能对应到语法点的错误，就可以接上已有的补救和再测流程。 |
| D68 | **把握中等以上、并且不是“小问题”的写作语法问题才进入错误本**；写作水平估计至少要 3 篇，置信度固定为低 | 规格 §10.4：低置信度结果不进入能力计算，单次模型判断不能改变等级。 |
| D69 | **所有 AI 生成内容先成草稿**，用和内置材料同一套规则校验，学习者预览确认后才发布；AI 释义按“词 + 句子”缓存 | 规格 §10.3：不能跳过结构校验、来源记录和草稿状态；缓存避免重复付费。 |
| D70 | **AI 微课的题目只属于本人**（`exercises.owner_user_id`），不进公共题库，种子更新也不会动它们 | 生成内容没有经过内容审核，不能混进审核过的题库。 |
| D71 | **实时语音的 SDP 交换由服务端完成**：浏览器把 offer 发给本应用，服务端申请 60 秒、只用一次的临时凭证，交换完即丢弃，只返回 answer；语音本身仍由浏览器直连服务商 | 规格 §7.7 的短时效、单用途凭证都满足，而且浏览器连临时凭证都拿不到；CSP 的 `connect-src` 不用为服务商放开（它在构建时固定，没法按 `AI_BASE_URL` 调整）；兼容服务的地址也照常可用。 |
| D72 | **口语反馈只根据转写文字，不评价发音**；置信度最高为“中”、说得少时为“低”；问题必须引用学习者说过的话 | 文本模型听不到声音，发音评价不可靠（规格 §5.10“仅在模型可靠支持时”）；转写错误会影响判断；口音不能扣分，也不能冒充官方评分。 |
| D73 | **每次练习前单独确认是否保存转录 / 录音**（默认值在设置里，录音默认关）；录音只录学习者自己的麦克风；不保存转录时，反馈只用浏览器这一次传来的内容 | 规格 §11.2：录制前清楚说明保存什么、发给谁；不留存不需要的数据。删除录音时先删文件再删记录，两者保持一致（规格 §14.2）。 |
| D74 | **实时语音、转写、语音合成的费用记为“未知”**，用时长上限（`AI_REALTIME_MAX_MINUTES`）、每次练习 3 次连接、每人每 10 分钟 6 次连接来控制 | 这些按音频或时长计费，不能用文本 token 价格估算；实时会话在浏览器和服务商之间进行，服务端看不到用量，只能限制入口和时长。 |
| D75 | **模拟 AI 下的实时语音是浏览器里的模拟会话**，发出和真实服务相同的事件，由同一个状态机处理；E2E 用 Chrome 的假麦克风 | 不需要密钥和网络就能测试所有状态（打断、断线、降级、释放麦克风）；真实和模拟只差传输层。 |
| D76 | **朗读 / 跟读只用录音 + 转写 + 按词对照**，不走实时对话，页面写明“不是发音评分” | 这类任务要的是逐句对照，不需要对话；对照的是“转写识别到了哪些词”，不能当成发音分数。 |
| D77 | **能力证据从已有的练习记录里收集**（打开能力地图 / 进度页时幂等同步，每条能力 × 每条记录只有一行），而不是在每个练习服务里另写一遍 | 不用改动十几个练习入口，旧记录也能补出证据；每条证据都能链接回真实练习（规格 §14.3“学习统计能够追溯到真实练习记录”）。删除口语练习或写作时，证据随之删除。 |
| D78 | **能力描述 = 单元目标 + 自写的等级目录**；练习内容用 `can_do_ids` 声明它证明哪条能力，种子和测试交叉校验 | 只有 6 个单元，单元目标覆盖不了材料、口语、写作的 A2 / B1 内容；用自己的话写可以避免照抄 CEFR Companion Volume；写错 id 立即发现。 |
| D79 | **“已展示”的标准**：按权重计数（自评或低置信度算半次），至少 2 个不同的日子，最近 10 条正确率达标；口语、写作、转述、发音类还要至少一次非自评的证据；60 天没新证据标“很久没练” | 规格 §2.1 要求通过标准、置信度和最近验证时间；一次做对、一天里反复做或只靠自评都不能算掌握。状态不进入水平估计（规格 §10.4、§14.3）。 |
| D80 | **重新诊断在同一难度下优先出上次没做过的题**，没有就仍用旧题，不为了换题而偏离难度 | 自适应诊断的准确性优先；题库小，换题只能尽量。 |
| D49 | **引导不强制跳转**：今日页提示，可以随时跳过或继续 | 规格 §4.1 要求能暂停、跳过、继续；不挡住其他功能，也不影响已有的直达链接。 |
| D31 | **验收用独立的 Compose 项目**（`COMPOSE_PROJECT_NAME`、独立 env 文件、独立端口和卷），并用 `E2E_BASE_URL` 对部署实例跑 E2E | 模拟新机器，不影响开发库；脚本都支持 `ENV_FILE` 和 `COMPOSE_PROJECT_NAME`。 |

## 4. 目录约定

遵循规格 §7.2：

```text
src/
  app/            路由（(app) 为登录后应用区，(auth) 为登录/初始化区）
  components/     ui/（原语）、layout/（外壳与导航）、learning/、vocabulary/ …
  modules/        业务模块：domain / services / repositories / schemas / actions
  lib/            ai/、audio/、storage/、validation/、security/、config/ 与通用工具
```
